# 装备型号检索 · v0.4.0

[更新日志](CHANGELOG.md)

从当前选定的 AstrBot 知识库原文提取型号写法，在查询时补充对应候选。原问题完整保留；原生 Embedding、稀疏检索、候选结果和 Rerank 继续负责检索与排序。

**写法、组合与改型的具体处理见 [型号写法映射规则](MAPPING_RULES.md)**，其中包含连字符省略、数字斜线、完整组合与组成项、嵌套表达式及示例。

适配 AstrBot **4.29.3**（`>=4.29.3,<4.30`）。无额外 Python 依赖或插件专用 API Key。

## 使用

在 AstrBot 插件管理中手动上传或更新插件，在原生配置中选择知识库和 Rerank。无需重传资料或重建向量；无需逐个添加新装备名称。

| 配置项 | 默认 | 作用 |
|---|---:|---|
| `enabled` | true | 总开关 |
| `max_aliases` | 8 | 每次查询最多选取1–32个原文候选写法 |
| `aliases` | 内置少量别名 | 每项为“输入别名=资料写法”；仅在所选知识库含对应名称时扩展 |
| `llm_guidance` | true | 提示回答模型按完整型号、后缀、年代和来源归属参数 |
| `neighbor_chunks` | 1 | 检查同文档前后0–3块；0关闭邻接补取 |
| `context_budget` | 4 | 最多补入0–32个邻块参与原生Rerank；0关闭，无Rerank时不补取 |

完整组合与组成项分层保留。例如 `bt5/rs132` 可以匹配语料中的 `BT-5/RS-132`，同时记录独立出现的 `BT-5` 与 `RS-132`；`T-34/85` 则保留数字后缀。查询信息传入回答上下文，名称、安装、试验、拟议和比较关系由回答模型结合原文判断。通用说明只加入系统提示一次。

名称词表从原生知识库的本地 SQLite 分块提取。启动完成后在线程中预热已就绪知识库；热重载时也会预热。查询只使用所选库的词表，不含型号的问题跳过词表读取。数据库提交变更后，缓存核对各文档的分块更新时间，只重新读取和解析有变化的文档正文；删除文档会移除对应词表。元数据与正文在同一只读事务内读取，无法读取时沿用原生查询。查询始终只调用一次原生检索，不增加 Embedding 或 Rerank 请求次数；扩展写法会增加该次查询的输入文字。

数值配置无法解析时使用默认值，超出范围时限制到上表范围；`aliases` 支持字符串列表或逐行文本，忽略无效条目。

未匹配到语料名称时保留原问题。启用邻接补取且所选库有Rerank时，插件在原生融合后追加同文档邻块，保留所有原生候选，由原生Rerank决定最终条数及排序。例如原生融合返回20块，默认预算4最多送入24块；新增块的完整原文会增加本次Rerank处理量，可能影响费用与延迟。

邻块进入最终结果而其对应来源块未返回时，回答上下文会附加该来源原文，同一来源只附一次。邻接只表示文档位置关系，不证明两段属于同一型号。插件不按装备类别删除证据，不改正文、向量或分块器；型号归属仍须按文献核对。

卸载时恢复仍由本插件持有的检索/融合方法并关闭只读连接。旧版的 `lookback_chunks`、`candidate_limit`、`object_query_style` 配置不再使用；`neighbor_chunks` 在当前方案中范围为0–3。
